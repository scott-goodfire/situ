# Perftester Autoresearch Trial

Date: 2026-05-05

## Goal

Exercise Almanac against a real, small open-source project that can run locally
on a laptop, then use the result to find product and harness issues.

The selected target was `nyggus/perftester`, a lightweight Python package for
testing function runtime and memory usage. It was a good fit because it is small,
CPU-only, uses ordinary Python packaging, and has a native pytest/doctest suite.

Sandbox location:

```sh
~/sandbox/perftester-almanac-lab
```

## Setup

The target repo was cloned fresh into the sandbox:

```sh
git clone --depth=1 https://github.com/nyggus/perftester.git ~/sandbox/perftester-almanac-lab
cd ~/sandbox/perftester-almanac-lab
uv venv
uv pip install -e '.[dev]'
```

The native validation command was:

```sh
uv run python -m pytest
```

No Almanac-specific eval script was added to the target project.

## Baseline

The baseline native test command failed during collection:

```text
collected 12 items / 4 errors
ModuleNotFoundError: No module named 'pympler'
```

The source imports `pympler.asizeof` at import time, but the project dependency
list only included `easycheck`, `rounder`, and `memory_profiler`.

Interpretation: this was a real project setup/packaging problem, not an Almanac
artifact.

## Autoresearch Run 1

Objective:

```text
Get the perftester project native test suite collecting and passing, while
preserving the package public API.
```

Context:

```text
Inspect README.md and pyproject.toml. Use project-native commands only,
especially uv run python -m pytest. Preserve stdout/stderr as plaintext
evaluation evidence. Do not add Almanac-specific scripts. If dependencies are
missing, prefer a normal packaging fix in pyproject.toml over ad hoc local
installs.
```

Command:

```sh
uv run --package almanac-harness almanac exec ~/sandbox/perftester-almanac-lab \
  --json \
  --objective "Get the perftester project native test suite collecting and passing, while preserving the package public API." \
  --context "Inspect README.md and pyproject.toml. Use project-native commands only, especially uv run python -m pytest. Preserve stdout/stderr as plaintext evaluation evidence. Do not add Almanac-specific scripts. If dependencies are missing, prefer a normal packaging fix in pyproject.toml over ad hoc local installs." \
  --max-experiments 2 \
  --timeout 240
```

What Almanac did well:

- Created a baseline evaluation and recorded the raw pytest output as plaintext
  evidence.
- Created a hypothesis that the missing runtime dependency blocked collection.
- Created an experiment to declare `pympler` as a project dependency.
- Edited `pyproject.toml` to add `pympler`.
- Reran the native pytest command and showed collection improved from
  `12 items / 4 errors` to `20 items`.
- Identified that remaining failures were doctest/runtime expectation issues
  rather than public API breakage.

The first run timed out before it reached a clean final state. That was useful:
it exposed harness behavior we should improve around headless timeouts and DBOS
workflow recovery.

## Manual Completion

After the first Almanac run, I completed the candidate fix manually so the target
project had a known-green state.

The final sandbox diff is intentionally small:

```text
docs/benchmarking_against_another_function.md | doctest memory thresholds
docs/change_benchmarking_function.md          | doctest memory threshold
docs/most_basic_use_memory.md                 | doctest memory thresholds
docs/use_of_config.md                         | config doctest isolation
docs/use_of_pp.md                             | explicit print precision
pyproject.toml                                | add pympler dependency
tests/doctest_function_str.md                 | dynamic memory threshold
uv.lock                                       | generated by uv
```

The main fix was the missing dependency:

```toml
dependencies = ["easycheck", "rounder", "memory_profiler", "pympler"]
```

The remaining edits made doctests less machine-dependent by avoiding fixed memory
ceilings and by making config-sensitive expectations explicit.

## Autoresearch Run 2

Objective:

```text
Validate that the perftester native test suite is now passing after the
dependency and doctest-stability fixes.
```

Context:

```text
Do not edit files in this validation pass. Inspect the existing Almanac ledger
and run uv run python -m pytest as the project-native validation command. Record
stdout/stderr as plaintext evaluation evidence and summarize any residual
warnings or risks.
```

Command:

```sh
uv run --package almanac-harness almanac exec ~/sandbox/perftester-almanac-lab \
  --json \
  --objective "Validate that the perftester native test suite is now passing after the dependency and doctest-stability fixes." \
  --context "Do not edit files in this validation pass. Inspect the existing Almanac ledger and run uv run python -m pytest as the project-native validation command. Record stdout/stderr as plaintext evaluation evidence and summarize any residual warnings or risks." \
  --max-experiments 1 \
  --timeout 480
```

Result recorded by Almanac:

```text
20 passed, 2 warnings in 170.81s
```

I also reran the native command directly after a small cleanup:

```text
20 passed, 2 warnings in 163.70s
```

The warnings are multiprocessing `resource_tracker` warnings emitted during
memory-related doctests. They do not fail the suite, but they are worth noting if
this project were being prepared for an upstream PR.

## Harness Bugs Found And Fixed

The first timed-out headless run left a DBOS workflow pending. Later read-only
snapshot commands initialized the agent runtime, launched DBOS, and triggered
recovery of that stale workflow. That replayed tool side effects into the old
session and produced duplicate-looking session records.

Two harness fixes were made:

- `HarnessApp` now initializes `AgentRuntime` lazily, so read-only commands like
  `snapshot` do not launch DBOS or recover old workflows.
- Local DBOS runs now default to a per-process executor id, which prevents a
  timed-out demo process from being automatically replayed by the next CLI
  invocation.

Validation after the fix:

```sh
uv run python scripts/check-python-syntax.py
uv run --package almanac-harness almanac snapshot ~/sandbox/perftester-almanac-lab --json
```

The snapshot command no longer emitted DBOS recovery/shutdown errors.

## Product Findings

This was a useful target for Almanac because it had a real sequence:

```text
baseline fails to collect
  -> dependency hypothesis
  -> dependency experiment
  -> collection improves
  -> doctest instability remains
  -> stabilization hypothesis
  -> validation run
  -> green native suite
```

The run also reinforced a few product points:

- Plaintext evaluation evidence is the right MVP shape. The agent preserved
  stdout/stderr and interpreted it well without needing structured metric
  parsing.
- Evaluation records are useful as first-class objects. The important evidence
  in this run was "what did pytest say before and after this candidate?".
- A validation-only pass is useful. The second run was not about discovering a
  new idea; it was about independently recording that the current candidate
  passes.
- Headless timeout behavior needs to be first-class. A timeout should become a
  visible session/event state, not a half-active run that can be replayed later.
- The agent can make useful first fixes, but still benefits from a human review
  loop for expectation changes in docs/tests.

## Recommendation

This is a good ongoing smoke target for Almanac. It is small enough to run
locally, but realistic enough to exercise:

- repo inspection
- project-native command execution
- setup blocker diagnosis
- dependency changes
- doctest/test expectation review
- evaluation result recording
- validation-only runs
- headless timeout handling

For the next round, I would add a harness-level timeout event/state and a
read-only validation mode so agents can explicitly validate a candidate without
editing files.
